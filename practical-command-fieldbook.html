Practical Command Fieldbook

Six structured practice units · read-only diagnostics · simulated examples · evidence notes

Authorized practice only. Run commands exclusively on systems you own or have permission to assess. Command output shown here is illustrative, not live. The fieldbook does not execute commands. Notes stay in this browser's local storage; they do not constitute graded proof of competency.

01 · Linux navigation and evidence

Outcome: Distinguish location, identity, files, permissions and process context before making changes.

CommandWhat it does / whyIllustrative outputInterpretation and caution
pwdPrint working directory; it tells you where relative file paths begin.
/home/student
If this differs from your expected path, stop before opening or editing files.
ls -laList files, including hidden entries, with owners and permission bits.
drwxr-xr-x student student .
-rw-r--r-- student student notes.txt
A leading d means directory; - means regular file. Read and write permissions are different.
idShow numeric user and group identities.
uid=1000(student) gid=1000(student) groups=1000(student)
Do not assume admin rights; group membership influences file access.
ps -efShow current processes for correlation with services and log timestamps.
student  412  1  ... python3 app.py
A process name alone is not proof it is malicious. Verify ownership, origin and context.

Hands-on assignment: In your own isolated Linux lab, collect working directory, file permissions, identity and running processes. Write a four-line evidence summary; do not modify files.

Independent check: Which command reveals numeric user and group membership? Explain why this matters for a permission-denied event.

02 · DNS, routes and connectivity

Outcome: Separate name-resolution errors from transport failure instead of guessing that a website is down.

CommandWhat it does / whyIllustrative outputInterpretation and caution
ip addrDisplay interface addresses on Linux.
inet 192.0.2.20/24 dev eth0
192.0.2.0/24 is documentation-only space here; identify subnet before interpreting reachability.
ip routeShow how the host chooses its next hop.
default via 192.0.2.1 dev eth0
A missing default route affects traffic beyond the local network.
nslookup example.comQuery a DNS resolver for the domain.
Name: example.com
Address: 93.184.215.14
Returned addresses can change; a lookup succeeds even when the web service is unreachable.
curl -I https://example.comRequest just HTTP response headers.
HTTP/2 200
A success response confirms this particular request worked, not that every page or service is healthy.

Hands-on assignment: For a fictional laptop that resolves its domain but cannot connect, compare route, DNS and HTTPS observations and state the next safe diagnostic.

Independent check: If nslookup works but curl times out, what failure categories remain? Name at least two.

03 · Windows identity and event evidence

Outcome: Explain the purpose of PowerShell inventory and read-only event review.

CommandWhat it does / whyIllustrative outputInterpretation and caution
whoami /allIn Windows Command Prompt, show current identity, group SIDs and privileges.
USER INFORMATION: LAB\student
GROUP INFORMATION: Users
A listed privilege may be disabled; do not infer elevation from group names alone.
Get-LocalUserIn PowerShell, list local user accounts.
Name      Enabled
student   True
guest     False
A disabled account is not an active sign-in; document scope and timestamps.
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} -MaxEvents 5Read up to five failed sign-in events, where access to Security logs is permitted.
Id: 4625  TimeCreated: 2026-10-31 18:20
Event 4625 is a failed logon, not proof of an attack. Check LogonType, account, source and surrounding successful events.
Get-NetTCPConnection -State ListenList local TCP listeners.
LocalPort: 443  State: Listen
A listener does not prove exposure to the internet; firewall, interface and upstream rules matter.

Hands-on assignment: On an owned Windows test computer, inventory users, listeners and five synthetic or authorized sign-in records. Identify what evidence would disprove a brute-force hypothesis.

Independent check: Why can many failed sign-ins be a false positive? What additional fields matter?

04 · Python defensive automation

Outcome: Build read-only parsing logic and understand its limitations.

CommandWhat it does / whyIllustrative outputInterpretation and caution
python3 --versionCheck Python interpreter availability.
Python 3.x.x
The command reports installation; it does not validate any script.
python3 -m venv .venvCreate an isolated Python environment in your own lab folder.
(no output on success)
Virtual environments separate dependencies but are not strong security sandboxes.
python3 analyze.pyRun a locally authored read-only parser against fabricated records.
failed=3 unique_users=2

Hands-on assignment: Create analyze.py in your own practice folder using the sample code below. Alter three fabricated rows and verify your expected counts.

Independent check: What happens if the log uses a different delimiter or contains malformed rows? Explain how you would validate parsing.

05 · HTTP and authorization reasoning

Outcome: Tell authentication, authorization and session management apart without testing third-party sites.

CommandWhat it does / whyIllustrative outputInterpretation and caution
curl -I http://localhost:8000Read response headers from a server you started locally.
HTTP/1.0 200 OK
200 is a response status, not authorization evidence for protected routes.
curl -i http://localhost:8000/missingInspect status, headers and body for a local missing path.
HTTP/1.0 404 File not found
A 404 for a missing route does not establish whether an existing private resource is protected.
python3 -m http.server 8000 --bind 127.0.0.1Serve files only on the loopback interface in your own throwaway directory.
Serving HTTP on 127.0.0.1 port 8000
This is an unauthenticated static-file server: never serve secrets, credentials or sensitive folders. Stop with Ctrl-C.

Hands-on assignment: Start a server from an empty throwaway directory, request its index, then request a missing path. Record status codes and explain why this exercise does NOT test user authorization.

Independent check: Why must an object-level authorization test use two distinct authorized lab accounts and private objects?

06 · Incident triage and evidence quality

Outcome: Document a defensible timeline while separating observation from hypothesis.

CommandWhat it does / whyIllustrative outputInterpretation and caution
date -uRecord current UTC wall-clock time for a timeline.
Sun Nov 1 21:00:00 UTC 2026
Compare timezone and clock skew before correlating events; sample time is illustrative.
sha256sum sample.logHash a copied synthetic evidence file on Linux.
<64 hex characters>  sample.log
A hash helps detect change; it does not prove that collected data is genuine or complete.
wc -l sample.logCount lines in the evidence copy.
42 sample.log
Line count is not event count when records span multiple lines.
grep -n 'ERROR' sample.logLocate lines containing literal uppercase ERROR.
18:ERROR service unavailable
The search is case sensitive by default and may miss differently formatted events.

Hands-on assignment: Build a five-row timeline using fabricated timestamps, evidence source, event, confidence and alternative explanation. Propose a reversible containment step requiring approval.

Independent check: Explain the difference between an observable event, a hypothesis and a confirmed finding.

Python sample · parse fabricated sign-in records

Save as analyze.py in your own lab directory. This script processes its built-in fictional data only; it does not inspect any real log or remote computer.

rows = ["alice,FAIL", "bob,FAIL", "alice,OK", "alice,FAIL"]
failed = []
for row in rows:
    pieces = row.split(",")
    if len(pieces) != 2:
        continue
    name, result = pieces
    if result == "FAIL":
        failed.append(name)
print("failed=", len(failed), "unique_users=", len(set(failed)))

Expected result: failed= 3 unique_users= 2. This toy parser does not handle timestamps, CSV quoting or missing fields. Improve it with the standard csv library, test malformed input and avoid logging private identifiers in production.

Mastery evidence checklist

For each unit, a competent student should (1) explain each command, (2) predict output type, (3) collect lab evidence, (4) distinguish fact from inference, (5) justify a safe next action, and (6) reproduce findings independently. These are self-check prompts, not automatically scored assessments or certification.
