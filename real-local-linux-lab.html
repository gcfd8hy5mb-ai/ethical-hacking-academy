Real-system training · local Linux VM · first implementation

Launch your first real Linux practice lab

Move beyond scripted terminal output: create a Linux VM on your own computer, then run real Linux shell commands against training files inside that isolated machine. The Academy supplies a small, reproducible offline lab and a local checker.

This page cannot launch a VM from GitHub Pages or operate your laptop remotely. The commands below execute only when you personally enter them inside your own Linux VM. No paid cloud service is needed for the first lab.

1. Set up a safe virtual computer

Prepare the host

Use a desktop/laptop with virtualization support. Install a supported VM application and download an official Ubuntu Desktop or Server ISO from its publisher.

Isolate the guest

Assign roughly 2 CPU cores, 2–4 GB RAM and 20 GB virtual storage if your host permits. Set the network adapter to internal network / host-only for practice. Avoid bridged networking.

Install and snapshot

Install Ubuntu in the VM, apply updates using an explicitly temporary NAT connection if needed, then disconnect NAT and restore isolation before running labs. Take a clean snapshot.

An isolated switch alone does not guarantee full VM containment. Disable shared folders and clipboard, keep the hypervisor updated, and do not place sensitive files in the guest. Host-only mode can permit host/guest communication; internal-network mode is usually stricter.

On Windows or Linux, VirtualBox may be suitable. On a Chromebook, support varies by model and whether Linux virtualization is available; a Chromebook is not automatically suitable for running full nested virtual machines.

2. Install the actual lab exercises

After starting the isolated Ubuntu VM, copy the Python script using the repository link and save it as academy_lab.py inside the VM. You can download it while networking is enabled for setup, then disconnect networking before practicing.

Run the following commands in the Ubuntu VM's real terminal, not in the Academy browser simulation:

python3 --version
python3 academy_lab.py setup
python3 academy_lab.py status

The script uses only Python's standard library. It makes a folder in your VM user's home directory, does not require root, does not run a network service and never connects to another target.

New · Browser-accessible local VM console

Optional: Use a real local browser lab console

I've added academy_console.py, a small local server that gives you a TryHackMe-style browser interface inside your own Ubuntu VM. Its buttons perform actual file operations on the practice files and show real results. It intentionally does not expose a general-purpose command shell.

Preparation: Download both academy_lab.py and academy_console.py into the same directory inside the Ubuntu VM. Initialize the lab using the setup instructions above, or select Create training files from the local console.

View the local browser console Python script · Open raw script

# Run inside Ubuntu, from the folder containing both scripts:
python3 academy_console.py

# Then open a browser INSIDE THAT SAME VM:
# http://127.0.0.1:8765

Optional checks before opening the console: save test_academy_console.py alongside both Python scripts and run python3 -m unittest -v test_academy_console. View regression tests. These tests should be run inside your VM; they have not yet been executed on your hardware.

Security boundaries: the console binds to 127.0.0.1 only; it uses an in-memory request token, strict browser-origin checks and approved operations limited to the training folder. Never forward port 8765 to your host, LAN or the internet. Do not run it as root. Stop the server using Ctrl+C.

The public GitHub Pages Academy cannot open a local VM console by itself, especially across separate devices. For this phase, use a browser running inside the VM. Shared remote desktop access or website-to-VM connectivity needs a separate security design and is not implemented yet.

3. Complete three real-machine missions

Mission A · Linux permissions

Inspect the mode and contents of your training report. Repair its permissions so the owner can read/write, its group can read, and everyone else has no access.

cd ~/academy-local-lab
ls -l permissions/report.txt
chmod 640 permissions/report.txt
stat -c '%a %n' permissions/report.txt

Mission B · Log investigation

Examine a local mock DNS resolver log. Create logs/finding.txt explaining what the timeout evidence indicates and what it cannot prove.

cd ~/academy-local-lab
cat logs/resolver.log
nano logs/finding.txt

Mission C · Configuration repair

Inspect the intentionally invalid training configuration and correct the bad listen directive. This is an example file—no nginx server is installed or started.

cd ~/academy-local-lab
cat config/web.conf
nano config/web.conf

Validate and export

After completing all three missions, return to the folder containing academy_lab.py and run the local checker. The script prints a practice flag only when the file-state checks pass.

python3 academy_lab.py check
python3 academy_lab.py export

The log mission uses a basic text-content check, not semantic grading. A human reviewer should assess whether your explanation is technically correct.

4. Record practice completion

Enter the training flag printed by the VM checker. This validates a submitted answer against a fixed local exercise flag only; it does not authenticate a VM or verify that you actually performed the work.

The flag, notes and checklist below remain local to this browser. Existing lesson completions, exam grades and Firebase cloud records are untouched.
